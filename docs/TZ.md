## 1. Назначение и общее описание

Text2Reel — веб-платформа, которая превращает текстовый сценарий в готовый видеоролик. Пользователь вставляет текст, выбирает визуальный стиль и формат площадки (YouTube, TikTok/Reels/Shorts, Instagram). Дальше система сама:

1. С помощью LLM разбивает сценарий на сцены и пишет для каждой визуальное описание.
2. Генерирует изображение для каждой сцены в едином стиле.
3. Синтезирует озвучку с естественными паузами.
4. Собирает видео через FFmpeg: анимация кадров, переходы, субтитры, фоновая музыка, брендинг.
5. Отдаёт MP4, готовый к публикации.

### 1.1. Проблема
Для коротких роликов (объясняющих видео, историй, обзоров, контента для соцсетей) автору приходится вручную подбирать визуал, записывать голос, монтировать и делать субтитры. На минуту видео уходит 1–3 часа. Коммерческие сервисы (Pictory, InVideo, Fliki) платные, работают по подписке и не всегда хорошо поддерживают русский язык.

### 1.2. Цель проекта
- **Продуктовая:** готовый ролик длиной 30–90 секунд из текста за несколько минут, без навыков монтажа и дешевле 10 ₽ за ролик.
- **Учебная:** освоить AI-генерацию изображений, синтез речи, видеообработку через FFmpeg, построение многошаговых медиапайплайнов с очередями и оптимизацию производительности и стоимости.

### 1.3. Целевая аудитория
| Сегмент | Задача |
|---|---|
| Авторы контента в соцсетях | Регулярно выпускать Shorts, Reels и TikTok по текстовым идеям |
| Малый бизнес и эксперты | Объясняющие ролики о продукте или услуге с логотипом |
| Преподаватели и блогеры | Иллюстрированные истории и мини-лекции |
| Маркетологи | Быстрые A/B-варианты роликов в разных стилях и форматах |

### 1.4. Принцип формирования видеоряда
Видео **не генерируется покадрово**. На каждую сцену создаётся **одна** AI-иллюстрация, примерно 10 на минуту ролика. Движение добавляет FFmpeg:
- **эффект Ken Burns** (`zoompan`): плавный зум и панорама по картинке на всю длительность озвучки сцены, 30 fps;
- **переходы** между сценами (`xfade`);
- **субтитры, музыка и брендинг** накладываются поверх.

Почему не покадрово: минута видео — это 1 800 кадров. Генерировать каждый кадр примерно в 180 раз дороже, а соседние кадры получились бы разными, и изображение мерцало бы. Модели image-to-video (Kling, Seedance, Wan, Runway) дают «живое» движение, но дороги и медленны. Они исключены из проекта (см. §3.2).

## 2. Цели и измеримые KPI

| # | KPI | Целевое значение (MVP) | Как измеряем |
|---|---|---|---|
| K1 | Время генерации ролика 60 с (≈10 сцен, 1080p) | **≤ 3 мин** от нажатия «Создать» до готового MP4 | Сумма времени шагов (`Project.timings_json`: разбивка, кадры и озвучка, монтаж), медиана по 10 прогонам: `python -m app.cli stats` |
| K2 | Себестоимость ролика 60 с | **≤ 10 ₽** (LLM + картинки + TTS) | Учёт токенов и картинок в `Project.cost_rub`: `python -m app.cli stats` |
| K3 | Доля успешных рендеров | **≥ 95 %** | Отношение `done` к `done + failed` среди `RenderJob` (`stats`), 20+ прогонов |
| K4 | Рассинхрон субтитров и голоса | **≤ 150 мс** | Ручная проверка 5 роликов и сравнение таймингов TTS с ASS |
| K5 | Консистентность стиля | ≥ 4 из 5 по оценке 3 человек | Опрос по 5 роликам: «кадры выглядят как один ролик?» |
| K6 | Параллельные рендеры без падений | **≥ 3** одновременно на VPS 4 vCPU / 8 GB | Бенчмарк `tests/benchmark_render.py` (workflow `Render benchmark`) |
| K7 | Время ответа API (кроме рендера) | p95 ≤ 300 мс | Логи uvicorn |
| K8 | Время от входа до первого ролика у нового пользователя | ≤ 5 мин | Юзабилити-тест с 3 людьми |

## 3. Границы проекта

### 3.1. Входит в MVP (in scope)
- Ввод сценария текстом или из файла `.txt`/`.docx`, до 5 000 символов.
- Русский и английский язык сценария и озвучки.
- 6 визуальных стилей: реализм, аниме, акварель, комикс, 3D-рендер, минимализм/флэт.
- 3 формата: 9:16 (1080×1920), 16:9 (1920×1080), 1:1 (1080×1080).
- Редактирование сцен до рендера: текст, визуальный промпт, перегенерация одной картинки.
- Предпросмотр таймлайна: дорожки сцен, озвучки и субтитров.
- Прогресс рендеринга по шагам в реальном времени.
- Библиотека фоновой музыки (10–15 треков под свободной лицензией), автоподбор по настроению.
- Брендинг: логотип, цвет и шрифт субтитров, интро- и аутро-карточка.
- История проектов, скачивание MP4 и SRT.
- Демо-доступ по логину и паролю.

### 3.2. Не входит в MVP (out of scope)
- Генерация видео нейросетями (text-to-video и image-to-video: Runway, Kling, Seedance, Wan), в том числе как опция. Решение от 2026-11-02: используем статичные кадры с анимацией Ken Burns (см. §1.4).
- Клонирование голоса, липсинк, аватары-ведущие.
- Регистрация, биллинг, тарифы, многопользовательские команды.
- Автопубликация на YouTube, TikTok и Instagram (только скачивание файла).
- Полноценный нелинейный видеоредактор (drag-n-drop по таймлайну, обрезка клипов).
- Мобильное приложение.
- Ролики длиннее 3 минут.

### 3.3. Ограничения
- Внешние AI-сервисы: LLM через **ProxyAPI**, изображения через Fal.ai или ProxyAPI, TTS через Edge TTS. Если они недоступны, система деградирует: повторные попытки, запасная модель, понятная ошибка в UI.
- Бюджет на AI API за время разработки: ≤ 2 000 ₽.
- Сервер: один VPS 4 vCPU / 8 GB RAM без GPU. Кодирование видео на CPU.
- Музыка и шрифты только под свободными лицензиями (CC0, Pixabay License, OFL).
- Контент проходит модерацию на стороне провайдеров генерации. Запрещённые промпты отклоняются.

### 3.4. Допущения
- У пользователя современный десктопный браузер (Chrome, Firefox, Safari последних 2 версий).
- Текст сценария осмысленный и связный. Система не исправляет бессвязный текст.
- Edge TTS остаётся бесплатным и доступным. Если нет, переключаемся на другой TTS через адаптер.

## 4. Пользовательские сценарии

**US-1. Быстрый ролик.** Как автор, я вставляю текст, выбираю «Аниме» и «9:16» и нажимаю «Создать», чтобы через 3 минуты скачать готовый Reels.

**US-2. Контроль сцен.** Как автор, я хочу увидеть разбивку на сцены до рендера, поправить текст и визуальное описание и перегенерировать неудачную картинку.

**US-3. Таймлайн.** Как автор, я хочу видеть таймлайн с длительностью каждой сцены, озвучкой и субтитрами, чтобы понимать, как будет выглядеть ролик.

**US-4. Прогресс.** Как пользователь, я хочу видеть, на каком шаге находится рендер (сцены → картинки → озвучка → монтаж) и сколько примерно осталось.

**US-5. Брендинг.** Как представитель бизнеса, я загружаю логотип и выбираю цвета, чтобы ролик был в фирменном стиле.

**US-6. Мультиформат.** Как маркетолог, я хочу из одного проекта получить версии 9:16 и 16:9, не генерируя картинки заново.

## 5. Функциональные требования

Нумерация `FR-<этап>.<номер>`. Приоритет: **M** (Must, обязательно для MVP), **S** (Should), **C** (Could).

### Этап 1. Разбивка сценария на сцены
| ID | Требование | Приоритет |
|---|---|---|
| FR-1.1 | LLM анализирует сценарий и делит его на сцены по 1–3 предложения (3–12 секунд озвучки) | M |
| FR-1.2 | Для каждой сцены LLM возвращает `narration`, `visual_prompt` (на английском), `mood`, `camera` | M |
| FR-1.3 | LLM формирует общий `style_bible`: персонажи, место действия, палитра. Он используется во всех промптах картинок | M |
| FR-1.4 | Ответ LLM валидируется по JSON-схеме. При невалидном ответе до 2 повторов, затем запасная модель | M |
| FR-1.5 | Текст озвучки совпадает с исходным сценарием (LLM не переписывает смысл), допускается только разбивка | M |
| FR-1.6 | Режим «улучшить сценарий» (LLM предлагает правки) | C |

### Этап 2. Генерация изображений
| ID | Требование | Приоритет |
|---|---|---|
| FR-2.1 | Генерация изображения на каждую сцену через провайдера картинок (Fal.ai FLUX или ProxyAPI) | M |
| FR-2.2 | Консистентность: префикс стиля + `style_bible` + общий seed + negative prompt | M |
| FR-2.3 | Кадрирование и масштабирование под выбранный формат (cover или blur-fill) | M |
| FR-2.4 | Параллельная генерация (до 4 одновременно) и кэш по hash(промпт, стиль, seed, размер) | S |
| FR-2.5 | Перегенерация одной сцены из UI | M |
| FR-2.6 | Загрузка собственной картинки вместо сгенерированной | C |

### Этап 3. Синтез речи
| ID | Требование | Приоритет |
|---|---|---|
| FR-3.1 | Озвучка каждой сцены через TTS (Edge TTS), выбор голоса (не меньше 2 RU и 2 EN) | M |
| FR-3.2 | Длительность сцены = длительность озвучки + паузы | M |
| FR-3.3 | Естественные паузы между сценами (300–600 мс) и на знаках препинания, настройка темпа (rate) и тона (pitch) | M |
| FR-3.4 | Получение таймингов слов (word boundaries) для субтитров | M |
| FR-3.5 | Нормализация громкости озвучки (loudnorm, −16 LUFS) | S |

### Этап 4. Видеомонтаж (compositor)
| ID | Требование | Приоритет |
|---|---|---|
| FR-4.1 | Сборка ролика через FFmpeg: кадр сцены + Ken Burns (zoom/pan) на длительность озвучки | M |
| FR-4.2 | Переходы между сценами (`xfade`: fade, slideleft, wipeleft, circleopen), выбор в шаблоне | M |
| FR-4.3 | Автоматические субтитры (ASS, прожигаются в видео) и отдельный SRT-файл | M |
| FR-4.4 | Субтитры «по словам» (подсветка текущего слова) для 9:16 | S |
| FR-4.5 | Фоновая музыка с приглушением под голос (ducking) | M |
| FR-4.6 | Выходной файл: H.264 + AAC, MP4, 30 fps, faststart | M |

## 7. Архитектура (кратко)
Frontend (React) → REST/SSE → Backend (FastAPI) → Redis → Celery workers → FFmpeg. Хранилище: SQLite в dev, PostgreSQL в prod, файлы на локальном диске. Подробности в [ARCHITECTURE.md](ARCHITECTURE.md).

Внешние сервисы:
- LLM: ProxyAPI, основная Claude Haiku 5.5, запасная DeepSeek V4.1 Flash
- Изображения: Fal.ai FLUX schnell или генерация изображений ProxyAPI
- TTS: Edge TTS

Обоснование выбора в [MODELS_AND_COSTS.md](MODELS_AND_COSTS.md).

## 8. Риски
| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Несогласованный стиль кадров | Высокая | Среднее | `style_bible`, фиксированный seed, единый префикс стиля, перегенерация сцены |
| Недоступность или изменение API (ProxyAPI, Fal, Edge TTS) | Средняя | Высокое | Адаптеры провайдеров, запасные модели, кэш, понятные ошибки |
| LLM возвращает невалидный JSON | Средняя | Среднее | JSON-схема, повторы, запасная модель, unit-тесты парсера |
| Медленный рендер на CPU | Средняя | Среднее | `-preset veryfast`, предварительное масштабирование кадров, отдельная очередь, превью 480p |
| Превышение бюджета API | Низкая | Среднее | Дешёвые модели, кэш, учёт стоимости, лимит проектов в демо |
| Модерация провайдера отклоняет промпт | Низкая | Низкое | Санитизация промпта, повтор с упрощённым промптом, заглушка-градиент |
| Лицензии на музыку и шрифты | Низкая | Высокое | Только CC0, Pixabay и OFL, список источников в `assets/music/LICENSES.md` |

## 9. Критерии приёмки MVP
1. По сценарию из 5–10 предложений в каждом из 6 стилей и 3 форматов получается MP4 с картинками, озвучкой, субтитрами, музыкой и переходами, без ошибок.
2. Сцены можно отредактировать и перегенерировать одну картинку до рендера.
3. В UI виден таймлайн и прогресс рендера по шагам.
4. Выполнены KPI K1–K3 (замеры в `docs/METRICS.md` к моменту сдачи).
5. Система развёрнута на сервере, демо-доступ работает.
6. Репозиторий публичный, README с инструкцией по запуску, библиотека промптов в `docs/PROMPTS.md`.

## 11. Глоссарий
| Термин | Значение |
|---|---|
| Сцена | Фрагмент сценария с одной картинкой и своей озвучкой |
| Style bible | Описание персонажей, места и палитры, общее для всех кадров |
| Ken Burns | Медленный зум и панорама по статичному изображению |
| xfade | Фильтр FFmpeg для переходов между клипами |
| ASS / SRT | Форматы субтитров (ASS поддерживает стили и анимацию) |
| Ducking | Автоматическое приглушение музыки во время речи |
| ProxyAPI | Российский шлюз к API OpenAI, Anthropic, Google, DeepSeek и других с оплатой в рублях |
